m9_pbm Physical RPF Sign-Error Model
1. Exec Summary

m9_pbm is now the strongest working baseline for reducing manual review

m9_pbm was developed because m7_dtr and m8_xgb performed well under a conference-paper time split, but did not transfer cleanly to held-out-substation Beta deployment.

Background

  • Alpha gives controlled sign-error ground truth, while Beta is the real oracle-review problem.
  • The conference time split tests new dates from the same substations; the harder Beta setup tests a held-out substation.
  • Beta sure is the cleaner development subset because ambiguous manual-review labels are excluded.

Method

  • m9_pbm generates candidate RPF windows for each substation-day and scores whether sign correction makes demand physically plausible.
  • The current C14 model uses nine interpretable features with simple weights, including stronger roughness weight and lighter substation-centering weight.
  • The operational goal is not perfect automation; it is to minimise manual checking by prioritising uncertain cases.

Result

  • Current working candidate: R2_beta_loso_plus_alpha / G_b1p0_r1p5_sc0p5.
  • Beta sure day result: P=0.8730, R=0.9274, F1=0.8994.
  • Window-quality checks are also strong: interval F1 0.8793 and energy IoU 0.8950.
2. Background And Datasets

Alpha gives controlled ground truth, while Beta tests the real oracle problem

Dataset Alpha

Alpha contains observed negative net-load readings. For sign-error modelling, negative readings can be converted to positive wrong-sign readings by taking their absolute value, while true RPF windows remain known.

Dataset Beta

Beta is the actual oracle dataset. It has no physically observed negative net-load ground truth for these sign-error cases, so labels come from manual review.

Beta sure means manually reviewed Beta substation-days where reviewer confidence is sure. It is the cleaner evaluation subset because the most ambiguous manual labels are excluded from the main development metric.

Time split

Train and test use the same substations, with roughly 90% of dates for training and 10% for testing. This checks temporal generalisation, not unseen-substation deployment.

Substation split

3. Goal And Evaluation

The aim is to minimise manual checking

The practical aim is to minimise manual checking, not to claim manual checking can be removed completely. The model should rank substation-days so high-confidence decisions can be accepted quickly and ambiguous days remain in a smaller review queue.

Primary model-selection metric: Beta leave-one-substation-out sure-only day-level F1. Beta all-days, interval F1, window IoU, energy F1, and energy IoU are secondary checks.

Day flag

Does this day contain an RPF sign-error window?

Start/end window

One predicted RPF interval per positive day.

Confidence or margin

How far the prediction sits from the selected threshold.

5. Method Overview

m9_pbm scores whether sign correction makes demand physically plausible

m9_pbm searches candidate windows during daytime. For each candidate window \(W\), it reconstructs the full-day underlying demand curve under two interpretations, then evaluates physical plausibility on \(W\) and its local shoulders.

\[ U_{\mathrm{no}}(t)=S(t)+y(t) \] \[ U_{\mathrm{corr},W}(t)= \begin{cases} S(t)-y(t), & t \in W \\ S(t)+y(t), & t \notin W \end{cases} \]
Notation:
  • \(t\): 15-minute timestamp within one day.
  • \(y(t)\): observed net load at time \(t\); wrong-sign RPF appears as a positive raw net-load bump.
  • \(S(t)\): solar generation at time \(t\).
  • \(W\): candidate RPF window, meaning a contiguous set of timestamps being tested for sign correction.
  • \(U_{\mathrm{no}}(t)\): reconstructed demand if no sign error is corrected.
  • \(U_{\mathrm{corr},W}(t)\): reconstructed demand after applying the sign correction only inside \(W\).
Real reviewed Beta RPF day. The corrected underlying demand curve is computed as \(S(t)-y(t)\) inside the window and compared against \(S(t)+y(t)\).
6. Scores And Thresholds

Each candidate window is scored with nine interpretable physical features

For each substation-day, the model generates many candidate windows. Each candidate receives nine feature values, combines them with simple weights, then selects the highest-scoring window for the day.

\[ \mathrm{Score}(W)=\sum_{i=1}^{9} w_i F_i(W) \] \[ \widehat{y}_{\mathrm{day}} = \begin{cases} 1, & \max_W \mathrm{Score}(W) \ge \tau \\ 0, & \max_W \mathrm{Score}(W) < \tau \end{cases} \]
Notation:
  • \(W\): one candidate RPF window from a substation-day.
  • \(F_i(W)\): value of feature \(i\), where \(i=1,\ldots,9\).
  • \(w_i\): fixed weight applied to feature \(F_i\) in the C14 scoring rule.
  • \(\mathrm{Score}(W)\): weighted physical-plausibility score for candidate window \(W\).
  • \(\max_W \mathrm{Score}(W)\): best candidate score found on the day.
  • \(\tau\): threshold for converting the best candidate score into a day-level RPF decision.
  • \(\widehat{y}_{\mathrm{day}}\): predicted day flag, with 1 = RPF day and 0 = non-RPF day.

7. Feature 1: Bridge Improvement

Bridge is the strongest single signal because true windows repair a demand gap

The bridge feature compares whether the corrected full-day demand curve joins more smoothly across the candidate window than the no-correction curve.

\[ E_{\mathrm{bridge}}(U,W)=\mathrm{median}_{t \in W}\left|U(t)-L_W(t)\right| \] \[ F_1(W)= \frac{E_{\mathrm{bridge}}(U_{\mathrm{no}},W)-E_{\mathrm{bridge}}(U_{\mathrm{corr},W},W)} {E_{\mathrm{bridge}}(U_{\mathrm{no}},W)+E_{\mathrm{bridge}}(U_{\mathrm{corr},W},W)+\epsilon} \]
Notation:
  • \(U\): either \(U_{\mathrm{no}}\) or \(U_{\mathrm{corr},W}\), depending on which reconstruction is being evaluated.
  • \(W\): candidate RPF window; \(t \in W\) means the timestamp is inside that window.
  • \(L_W(t)\): straight-line bridge between demand anchors just before and just after \(W\).
  • \(E_{\mathrm{bridge}}(U,W)\): median absolute distance between reconstruction \(U(t)\) and bridge line \(L_W(t)\) inside \(W\).
  • \(\epsilon\): small constant that prevents division by zero.
  • \(F_1(W)\): normalized bridge improvement; positive values mean correction makes the bridge more plausible.
  • Large positive \(F_1(W)\) means the corrected curve bridges the shoulders better.
  • It was the strongest separator in Beta sure-only days.

8. Feature 2: Roughness Improvement

Roughness improves window quality by rewarding smoother corrected demand

Roughness uses total variation over the candidate window plus local shoulders. Corrected demand should usually be less jumpy than the no-correction interpretation.

\[ TV(U,\Omega(W))=\sum_{t \in \Omega(W),\ t-\Delta t \in \Omega(W)} \left|U(t)-U(t-\Delta t)\right| \] \[ F_2(W)= \frac{TV(U_{\mathrm{no}},\Omega(W))-TV(U_{\mathrm{corr},W},\Omega(W))} {TV(U_{\mathrm{no}},\Omega(W))+TV(U_{\mathrm{corr},W},\Omega(W))+\epsilon} \]
Notation:
  • \(U\): demand reconstruction being evaluated, either no-correction or corrected-inside-\(W\).
  • \(W\): candidate RPF window.
  • \(\Omega(W)\): \(W\) plus short left/right context shoulders used to judge local smoothness.
  • \(\Delta t\): one sampling step, here 15 minutes.
  • \(TV(U,\Omega(W))\): total variation, or the sum of absolute step-to-step changes in \(U\) across \(\Omega(W)\).
  • \(\epsilon\): small constant that prevents division by zero.
  • \(F_2(W)\): normalized roughness improvement; positive values mean correction reduces roughness.
  • Roughness is a window-quality feature, not only a day detector.
  • The best grid result increased roughness weight to 1.5.

9. Feature 3: Slope-Continuity Improvement

Slope continuity penalises windows that introduce boundary jumps

A visually plausible correction should not create sharp slope discontinuities at the left and right edges of the selected window.

\[ J(U,W)= \left|m_{\mathrm{left}}(U,\Omega(W))-m_{\mathrm{in,left}}(U,W)\right| + \left|m_{\mathrm{right}}(U,\Omega(W))-m_{\mathrm{in,right}}(U,W)\right| \] \[ F_3(W)= \frac{J(U_{\mathrm{no}},W)-J(U_{\mathrm{corr},W},W)} {J(U_{\mathrm{no}},W)+J(U_{\mathrm{corr},W},W)+\epsilon} \]
Notation:
  • \(U\): demand reconstruction being evaluated.
  • \(W\): candidate RPF window; \(\Omega(W)\) is \(W\) plus local shoulders.
  • \(m_{\mathrm{left}}\), \(m_{\mathrm{right}}\): robust slopes estimated in the shoulders outside \(W\).
  • \(m_{\mathrm{in,left}}\), \(m_{\mathrm{in,right}}\): robust slopes estimated just inside the left and right edges of \(W\).
  • \(J(U,W)\): boundary slope-jump penalty for reconstruction \(U\).
  • \(\epsilon\): small constant that prevents division by zero.
  • \(F_3(W)\): normalized slope-continuity improvement; positive values mean correction improves boundary continuity.

Role in the model

Slope continuity is a guard against sharp, artificial-looking corrections. It is not the strongest standalone separator, but it helps keep selected windows physically coherent.

10. Feature 4: Duration Plausibility

Duration turns the short-window false-positive lesson into a soft score

Earlier diagnostics showed many Beta false positives were very short local wiggles. A soft duration feature favours sustained windows without completely banning short true events.

\[ F_4(W)=\min\left(1,\frac{\mathrm{duration}(W)}{1.5\ \mathrm{h}}\right) \]
Notation:
  • \(W\): candidate RPF window.
  • \(\mathrm{duration}(W)\): length of \(W\), measured in hours.
  • \(1.5\,\mathrm{h}\): soft reference duration; windows at or above this duration receive the maximum duration score.
  • \(\min(1,\cdot)\): caps the feature at 1 so duration cannot dominate the score by itself.
  • \(F_4(W)\): duration plausibility feature, ranging from 0 to 1.

Why soft, not hard?

Hard duration guards improved Beta precision but damaged Alpha recall because Alpha contains many valid short RPF events. The soft feature keeps that evidence without making it a brittle rule.

11. Feature 5: N-height Ratio

N-height captures the raw net-load bounce that many false positives lack

True RPF days often show raw net load rising into an N-shaped bounce inside the wrong-sign window. Many false positives have a much weaker bounce.

\[ F_5(W)= \mathrm{clip}_{[0,1]} \left( \frac{\max_{t \in W} y(t)-\max(y(t_{\mathrm{left}}),y(t_{\mathrm{right}}))} {\mathrm{scale}_{\mathrm{day/substation}}} \right) \]
Notation:
  • \(W\): candidate RPF window.
  • \(y(t)\): observed net load at timestamp \(t\).
  • \(\max_{t \in W} y(t)\): highest raw net-load value inside the candidate window.
  • \(t_{\mathrm{left}}\), \(t_{\mathrm{right}}\): timestamps at the left and right boundaries of \(W\).
  • \(\max(y(t_{\mathrm{left}}),y(t_{\mathrm{right}}))\): stronger of the two boundary net-load values.
  • \(\mathrm{scale}_{\mathrm{day/substation}}\): robust power scale from the current day and substation, used to normalize the bounce height.
  • \(\mathrm{clip}_{[0,1]}\): truncates the value to the range 0 to 1.
  • \(F_5(W)\): N-height ratio; larger values mean a stronger N-shaped raw net-load bounce.
  • It tests the visual FP/FN hypothesis directly.
  • It reduces weak low-bounce false windows.

12. Feature 6: Solar Strength Ratio

Solar strength keeps candidate windows tied to the physical driver

Wrong-sign RPF is physically most plausible when solar generation is strong. This feature down-weights windows during weak-solar periods.

\[ F_6(W)= \mathrm{clip}_{[0,1]} \left( \frac{p95\{S(t):t \in W\}}{\mathrm{median}_{d \in \mathrm{substation}}\ p95\{S_d(t):t \in \mathrm{daytime}\}+\epsilon} \right) \]
Notation:
  • \(W\): candidate RPF window.
  • \(S(t)\): solar generation at timestamp \(t\).
  • \(p95\{S(t):t \in W\}\): 95th percentile of solar generation inside \(W\).
  • \(d\): a day from the same substation's unlabelled history.
  • \(S_d(t)\): solar generation on historical day \(d\).
  • \(\mathrm{daytime}\): daylight timestamps used to estimate normal solar strength.
  • \(\epsilon\): small constant that prevents division by zero.
  • \(F_6(W)\): solar strength ratio after clipping to 0-1.

Role in the model

This is a plausibility guard, not a substation-specific labelled threshold. It makes weak-solar lookalikes less attractive while preserving the same scoring framework.

13. Feature 7: Solar Peak Alignment

Solar peak alignment favours windows near the daily solar maximum

RPF sign-error windows should usually be near the time when solar export pressure is highest, so the score favours candidates centred near the daily solar peak.

\[ F_7(W)= \mathrm{clip}_{[0,1]} \left( 1-\frac{\left|\mathrm{mid}(W)-t_{\mathrm{peak},S}\right|}{3.5\ \mathrm{h}} \right) \]
Notation:
  • \(W\): candidate RPF window.
  • \(\mathrm{mid}(W)\): midpoint time of \(W\).
  • \(t_{\mathrm{peak},S}\): timestamp of peak solar generation on that day.
  • \(|\mathrm{mid}(W)-t_{\mathrm{peak},S}|\): time distance between candidate midpoint and solar peak.
  • \(3.5\,\mathrm{h}\): soft timing scale used to convert peak distance into a score.
  • \(\mathrm{clip}_{[0,1]}\): truncates the score to the range 0 to 1.
  • \(F_7(W)\): solar peak alignment feature; larger values mean closer alignment with peak solar generation.

Role in the model

The feature is deliberately soft. It aligns search with the physical cause without forcing every event to be perfectly centred on noon or the solar peak.

C14 weight 1.0soft timing guard

14. Feature 8: Substation-Centered Core Score

Substation-centering makes physical scores more comparable across substations

Some substations have naturally higher or lower core physical scores. Substation-centering subtracts the unlabelled substation median before using the score.

\[ \mathrm{core}(W)=F_1(W)+F_2(W)+F_3(W) \] \[ F_8(W)=\mathrm{robust\_bound} \left( \mathrm{core}(W)-\mathrm{median}_{d \in \mathrm{substation}}\left(\max_{W_d}\mathrm{core}(W_d)\right) \right) \]
Notation:
  • \(W\): candidate RPF window on the current day.
  • \(F_1(W)\), \(F_2(W)\), \(F_3(W)\): bridge, roughness, and slope-continuity feature values.
  • \(\mathrm{core}(W)\): uncentred physical core score from the first three features.
  • \(d\): a day from the same substation's unlabelled history.
  • \(W_d\): a candidate window from historical day \(d\).
  • \(\max_{W_d}\mathrm{core}(W_d)\): best core score on historical substation-day \(d\).
  • \(\mathrm{median}_{d \in \mathrm{substation}}\): median across unlabelled days from the same substation.
  • \(\mathrm{robust\_bound}(\cdot)\): bounding step that limits extreme centred values.
  • \(F_8(W)\): substation-centered core feature.

Current C14 role

The small weight grid kept this feature, but reduced its weight to avoid over-normalising the signal.

15. Feature 9: Substation-Rank Core Score

Substation-rank was useful diagnostically, but the current best model drops it

Substation-rank converts each substation's best daily core score into a within-substation percentile rank. It was tested to make substation behaviour more comparable.

\[ F_9(d)=2 \cdot \mathrm{percentile\_rank}_{\mathrm{substation}} \left(\max_{W_d}\mathrm{core}(W_d)\right)-1 \]
Notation:
  • \(d\): current substation-day being scored.
  • \(W_d\): a candidate window on day \(d\).
  • \(\mathrm{core}(W_d)\): uncentred core score for candidate window \(W_d\).
  • \(\max_{W_d}\mathrm{core}(W_d)\): best core score on day \(d\).
  • \(\mathrm{percentile\_rank}_{\mathrm{substation}}\): percentile rank of that day within the same substation's unlabelled daily score distribution.
  • \(2 \cdot \mathrm{rank}-1\): rescales percentile rank from 0-1 into -1 to 1.
  • \(F_9(d)\): substation-rank core feature; current C14 weight is 0.

Current C14 decision

The feature separates RPF and non-RPF days in summary statistics, but the C14 weight grid found better held-out Beta performance when its weight was set to zero.

16. Experiments And Key Results

A small physical-score weight grid gave the best result without adding black-box complexity

LOSO means leave-one-substation-out. For each Beta fold, one substation is held out for testing. The threshold is tuned on the other Beta substations, optionally with Alpha added, then evaluated on the held-out substation.
