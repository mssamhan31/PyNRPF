Model development brief

m9_pbm Physical RPF Sign-Error Model

Static professional brief generated on 2026-07-07. Scope: day-level RPF sign-error detection, interval/window quality, confidence triage, and current journal-readiness.

1. m9_pbm is now the strongest working baseline for reducing manual review

m9_pbm was developed because the previous models, m7_dtr and m8_xgb, performed well under the conference-paper synthetic time split, but reached a performance ceiling when tested under station split and actual Dataset Beta deployment conditions.

The new model is physics-based. It searches candidate RPF windows and scores whether flipping the apparent wrong-sign net-load contribution creates a more plausible underlying demand curve. The aim is not to remove manual checking entirely, but to reduce it substantially by prioritising high-confidence automatic decisions and routing low-confidence days to review.

3. The optimisation target is day F1, with confidence used to reduce review workload

The practical aim is to minimise manual checking, not to claim that manual checking can be removed completely. The model should rank site-days so that high-confidence decisions can be accepted quickly, while ambiguous low-confidence days remain in a smaller review queue.

Primary model-selection metric: Beta leave-one-site-out sure-only day-level F1. This keeps model selection focused on the actual deployment dataset while avoiding the most subjective labels. Beta all-days, interval F1, window IoU, energy F1, and energy IoU are reported as secondary checks.

The model should output three things for each site-day:

Day flag
Does this day contain an RPF sign-error window?
Start/end window
One predicted RPF interval per positive day.
Confidence or margin
How far the prediction sits from the selected threshold.

The manual-review process becomes a triage process

Step What happens How it reduces manual checking
1. Score every site-day The model proposes no RPF or one RPF window, plus a confidence margin. All days are processed automatically in one batch.
2. Auto-accept high-confidence decisions Very confident positives and negatives can be accepted first. The review queue shrinks to the uncertain boundary cases.
3. Review low-confidence days A human checks only days near the threshold, plus selected audit samples. Manual effort is targeted to the days where it is most valuable.
4. Re-run after label corrections If review discovers label mistakes, regenerate Beta/Gamma and re-score. The process improves the oracle dataset as well as the model.

Day F1 is the optimisation metric; interval and energy metrics are guardrails

Metric Formula / definition Why it matters
Day precision, recall, F1 Precision = TP / (TP + FP), recall = TP / (TP + FN), F1 = 2PR / (P + R) Main selection metric for deciding whether a site-day should be reviewed or corrected.
Interval precision, recall, F1 Same formulas, but over 15-minute interval flags. Checks whether the predicted start/end window is useful, not only the day flag.
Window IoU IoU = overlap(actual window, predicted window) / union(actual window, predicted window) Direct overlap measure for the predicted RPF window.
Energy F1 / Energy IoU Same overlap idea, but using MWh correction area instead of interval count. Weights mistakes by correction magnitude, which is closer to practical energy impact.

Across the current experiments, the best model rankings are usually consistent across day F1, interval F1, energy F1, and energy IoU. This is useful: day-level F1 can remain the primary optimisation target without hiding major window-quality failures.

Confidence turns prediction into review prioritisation

Confidence is the distance between a daily score and the selected threshold. High-confidence positive or negative decisions can be auto-accepted first; low-confidence days remain candidates for manual review.

This changes the operational goal from "perfect automation" to "review fewer, more important days".

4. m9_pbm scores whether sign correction makes demand physically plausible

m9_pbm is a physical score model. It searches candidate windows during the daytime and asks: if this window were a wrong-sign RPF interval, would flipping the sign produce a more plausible underlying demand curve?

Let \(\ S(t)\ \) be solar generation and \(\ y(t)\ \) be the recorded net load.

Outside a candidate window \(\ W\ \):
\(\ U(t)=S(t)+y(t)\ \)

Inside \(\ W\ \), compare two interpretations:
\(\ U_{\mathrm{no}}(t)=S(t)+y(t)\ \)   uncorrected underlying demand
\(\ U_{\mathrm{corr}}(t)=S(t)-y(t)\ \)   corrected underlying demand if the sign is wrong

Each candidate window receives a physical score based on whether \(U_{\mathrm{corr}}\) looks more plausible than \(U_{\mathrm{no}}\). The best candidate is selected for the day, then compared with a threshold. The output is either no RPF or one RPF window.

Real reviewed Beta RPF day. The shaded window is the reviewed RPF interval. The corrected underlying demand curve is computed as \(S(t)-y(t)\) inside the window and is compared against the uncorrected interpretation \(S(t)+y(t)\).

5. Bridge is the strongest single signal because true windows repair a demand gap

The bridge feature measures whether the corrected demand curve joins more smoothly from the left side of the candidate window to the right side. A true RPF sign-error window should often look like a "hole" in the underlying demand curve that is repaired by sign correction.

\(B(W)=E_{\mathrm{bridge}}(U_{\mathrm{no}},W)-E_{\mathrm{bridge}}(U_{\mathrm{corr}},W)\)

Large positive \(B(W)\) means the corrected curve bridges the left and right shoulders better than the uncorrected curve.
  • Why it works: wrong-sign intervals often break the implied demand curve; correcting the sign repairs it.
  • Empirical result: bridge is the strongest separator in Beta sure-only days.

6. Roughness improves window quality by rewarding smoother corrected demand

Roughness uses total variation or mean absolute changes in the reconstructed demand curve. The physical assumption is simple: the corrected underlying demand should usually be less jumpy than the uncorrected interpretation.

\(TV(U,W)=\sum_{t \in W^+}|U(t)-U(t-\Delta t)|\)

\(R(W)=TV(U_{\mathrm{no}},W)-TV(U_{\mathrm{corr}},W)\)
  • Model role: roughness is a window-quality feature, not just a day detector.
  • Learning: the best grid result increased roughness weight to 1.5, which helped interval and energy metrics.

7. N-height captures the raw net-load bounce that many false positives lack

N-height captures the visual pattern repeatedly seen in FP/FN review: on true RPF days, the raw net load often rises into an N-shaped bounce inside the wrong-sign window. Many false positives have a much weaker bounce.

\(H_N(W)=\frac{\max(y_W)-\max(y_{\mathrm{left}},y_{\mathrm{right}})}{\mathrm{scale}_{\mathrm{site/day}}}\)

Here \(y_W\) is raw net load inside the candidate window; \(y_{\mathrm{left}}\) and \(y_{\mathrm{right}}\) are the window-edge values.
  • Why it matters: it directly tests the "raw net load bounces upward during RPF" observation.
  • Risk it controls: weak, low-bounce windows that look smooth but are not true RPF.

8. The remaining features act as interpretable guardrails around the core physics score

The non-core features are not meant to replace bridge, roughness, and N-height. Their role is to keep the selected window physically plausible and comparable across sites.

Window plausibility guards

Duration

Encodes that plausible RPF windows are not usually extremely short. Hard duration guards were explored, but the best result uses duration as a soft score component.

\(D(W)=\min(1,\mathrm{duration}(W)/1.5\mathrm{h})\)

Solar strength

Penalises weak-solar candidates. The sign-error phenomenon is most credible under high solar generation, especially clear-sky midday periods.

\(S_{\mathrm{ratio}}(W)=p95(S_W)/p95_{\mathrm{site}}(S)\)

Solar peak alignment

Rewards windows centred near the solar peak. This keeps the search aligned with the physical cause of reverse power flow.

\(A(W)=1-\mathrm{dist}(\mathrm{mid}(W),\mathrm{peak}_S)/3.5\mathrm{h}\)

Site comparability guards

Site-centered score

Subtracts a site baseline using unlabelled site score distribution. This is not a site-specific labelled threshold; it is a scale/behaviour normalisation.

\(C_{\mathrm{site}}(d)=\mathrm{core}(d)-\mathrm{median}_{\mathrm{site}}(\mathrm{core})\)

Site rank score

Uses within-site percentile rank to make scores more comparable across sites. It was useful in earlier bridge development.

\(R_{\mathrm{site}}(d)=\mathrm{percentile\_rank}_{\mathrm{site}}(\mathrm{core}(d))\)

Slope continuity

Useful as a secondary guard for jumpy windows, but not a strong positive discriminator by itself. In Beta sure-only, its median difference was negative.

\(SC(W)=\mathrm{slope\_jump}(U_{\mathrm{no}})-\mathrm{slope\_jump}(U_{\mathrm{corr}})\)

The main finding is that physical interpretability and performance improved together

  • Bridge is the strongest single physical signal. It directly tests whether the candidate correction creates a plausible demand bridge.
  • Roughness improves window quality. It helps interval and energy metrics even when it is not the strongest standalone day feature.
  • N-height supports the visual FP/FN hypothesis. True RPF windows usually contain a stronger raw net-load bounce than false positives.
  • Border-minimum behaviour is diagnostic but not yet a successful hard rule. True manual windows often align with local minima, but hard filtering removed too many useful predictions.
  • The best current model is suitable as a working baseline. Broad model searching should pause unless manual review reveals a clear repeatable error pattern.
