# Phase 0 decisions — 2026-09-16

Written before any labelled run in `m9_dev/`. Not reopened during this cycle.

## Design intent

1. Human parity: Beta `sure` reverse power flow (RPF) days are the human-obvious set. The first-priority failure is a `sure` day the model misses or is not confident about.
2. Consistency: a change is adopted only if it does not reduce `sure`-day recall or energy precision on any station with at least one `sure` RPF day, and improves the pooled metric or a named failure class.
3. Complexity: admitted only with (a) a named mechanism, (b) an ablation showing a named failure class returns without it, and (c) no harm to any other station. One to three components maximum.
4. Iteration: failure-class driven, at most five rounds, one remedy per round, each logged in `notes/`.
5. Beta `sure` drives the loop; Alpha pooled Energy IoU and energy precision must stay within 0.01 of baseline.
6. Beta `unsure` may be inspected for diagnosis; never used for tuning, selection or headline claims.

Failure priority: missed obvious case → false correction → wrong window → right but not confident.

| Scan range | slots 24–71 inclusive (06:00 to 18:00 exclusive); slots 23 and 72 are anchors only |
| Candidate set | NO_CORRECTION plus all 1,176 contiguous windows |
| Tie rules | null beats window; shorter beats longer; earlier beats later |
| Time budget | one working day |

## Energy metric definitions (provisional per PRD, used throughout this cycle)

Per 15-minute slot the correction changes the reading by 2·y, so correction energy on a slot is 2·y·0.25 MWh. Proposed MWh sums over proposed slots; required MWh over labelled slots; correctly corrected MWh over slots that are both. Energy IoU = correct / (proposed + required − correct). Energy precision = correct / proposed. Pooled values sum energies across site-days before dividing.
