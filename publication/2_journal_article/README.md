# PyNRPF journal article

The station-held-out evaluation of three methods for detecting and correcting a wrong reverse
power flow (RPF) sign in substation interval data: M7 (a deterministic threshold rule), M8
(a two-stage XGBoost classifier) and M9 (the counterfactual bridge method of the `pynrpf`
package). Every table, figure and number in the journal article traces to the files in
`results/`, and every one of them is regenerated by the notebooks in `notebooks/`.

## Problem and audience

Rooftop solar can push a distribution substation into reverse power flow. Some meters store
that export with the wrong sign, so recorded net load looks like demand. This folder measures
how well each method finds and corrects such days on stations it has never seen, judged on
real errors that two reviewers were sure about. It is written for a peer reviewer reproducing
the paper, for Ausgrid deciding what to run, and for the author returning to it later.

## Installation

From the repository root:

```powershell
python -m venv .venv
.\.venv\Scripts\Activate.ps1
python -m pip install -e .[dev,paper]
```

## Quick start

Two notebooks regenerate every paper artefact from the committed reference run in minutes:
`notebooks/paper_figures.ipynb` and `notebooks/paper_tables.ipynb`. Five notebooks
regenerate the reference run itself, in order: `01_data_and_folds`, `02_baselines_m7_m8`
(the long one, nine M8 fits), `03_m9`, `04_outcomes_and_metrics`, `05_gamma_forecasting`.
Each opens with its purpose, inputs, outputs and runtime, and has `CONFIG` in its first code
cell. The same stages run without a notebook:

```powershell
python -c "from paper import config, stages; stages.metrics(config.load())"
```

Expected result: `results/04_metrics/gate.json` says "M9 is the default method" and
`results/paper/tables/table02_headline.md` holds the headline table.

## Structure

```
config/evaluation.yaml   the one configuration: dataset hashes, fold rule, M7 and M8 settings, the M9
                         settings, the control c, the gate, the Gamma forecast settings, the operating points
dataset/                 final/ (Alpha, Beta, Gamma) and the oracle export behind the Beta and Gamma labels
paper/                   the code the notebooks call (below)
notebooks/               five pipeline notebooks and two artefact notebooks, committed without outputs
results/                 the reference run: one folder per stage, paper/ with the manuscript's figures and
                         tables (paper/supplementary/ for the rest), manifests/
sandbox/                 development history and dated studies; not maintained, not cited (see its README)
```

| module | does |
|---|---|
| `paper/config.py` | loads the YAML, verifies dataset hashes, resolves the stage folders |
| `paper/data.py`, `folds.py` | the common site-day population; the 18 station-held-out folds and their manifest |
| `paper/baselines/m7.py`, `m8.py`, `m8_features.py` | the two previous methods, M8 trained per fold on Beta only |
| `paper/m9.py` | M9 scored with `pynrpf`, calibrated per fold, decided at the control |
| `paper/reference.py` | applied corrections against the reference: energy terms, window agreement, minimum demand |
| `paper/metrics.py`, `operating_points.py` | pooled, per-station and macro metrics, bootstrap, coverage, gate, sensitivity, reliability; the precision-target study |
| `paper/gamma.py` | the forecasting case study |
| `paper/manuscript.py` | the numbered figures and tables of the manuscript, drawn at journal column width |
| `paper/figures.py`, `tables.py`, `style.py` | the registries (manuscript and supplementary) and the journal style |
| `paper/results.py`, `manifest.py`, `stages.py` | readers of finished stages; stage manifests with repository-relative paths and hashes; one function per stage |

## Evaluation design, in brief

Each of the 18 stations (ten Alpha, eight Beta) is held out once. Every method scores the
held-out station's complete site-days; M8 is retrained and M9's two calibration numbers are
refitted per fold on the other Beta stations only, and an Alpha station is scored with the
fit on all eight Beta stations, so nothing is ever fitted on Alpha. Beta sure days are the
headline population; unsure days appear only in a sensitivity table. The main metric is
Energy IoU; energy precision is gated at 0.90 on Beta sure days; site-day precision, recall
and F1 sit beside them, with station-bootstrap intervals. The operating-point study turns a
precision target into a control value and reports what it costs in review days and recall.

## Data

`dataset/final/` holds the three anonymised Ausgrid datasets with a `sha256.txt` the
configuration checks; `dataset/oracle_data_creation/` holds the publication-ready export of
the manual review behind the Beta and Gamma labels. See `docs/data.md` at the repository
root.

recorded hash and that the M9 headline row reproduces from the site-day table.
